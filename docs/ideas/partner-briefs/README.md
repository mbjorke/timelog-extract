# Partner briefs (working hypotheses)

**Status:** Product / partnership ideas — **not** commitments, outreach copy, or pricing.

**Scope:** Public-safe partner shapes for review and prioritization. Put **LinkedIn drafts, term sheets, raw hour benchmarks, and negotiation notes** in local `private/` (see `docs/meta/private-local-notes.md`).

**Goal (product):** **self-serve subscription revenue** (product-led growth), not funding the maintainer's consulting time. That is a deliberate correction: an earlier version of this file named "sustainable full-time work on Gittan" as the goal, which reads as a services business and pointed prioritization the wrong way.

**Operating constraint:** the scarce resource is **maintainer attention**, not code throughput. Deciding what to build and verifying it landed correctly costs more than writing it. Weigh any partner shape by how much maintainer attention it consumes before weighing its upside. See the 2026-08-06 priority pass (#513) for how this reorders the backlog.

## Two partner shapes, not one

"Partner" is used here for two different things. Keep them separate.

1. **A partner company** (the briefs below): an existing product business where there is overlap worth exploring, whether that ends in licensing, co-development, an export contract, or nothing.
2. **An unfilled commercial role** (no brief, by design): the missing capability is **online SaaS distribution**, meaning self-service, product-led growth, subscription. It is explicitly **not** relationship selling, and it is not something the briefs below can supply. Whoever fills it has to run the partner track and the compete track against the same companies in parallel.
